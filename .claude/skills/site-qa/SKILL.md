# Проверка качества

## Перед каждым пушем

1. `npm run check` — данные без ошибок.
2. `npm run build` — сборка проходит (≈2 800 страниц).
3. `npm run qa` (или `npm run qa -- /нужная-страница.html …`) — скриншоты в `qa-shots/` на 360, 393 и 1366 px, отчёт о горизонтальной прокрутке.
4. **Посмотреть скриншоты глазами** (Read). Проверить:
   - кнопки в один ряд на 360 px, тексты не переносятся по слогам, цены не переносятся;
   - отступы одинаковые, нет пустых блоков и висящих заголовков;
   - картинки одного масштаба в сетках, ничего не обрезано;
   - нижняя панель контактов на телефоне ничего не перекрывает.
5. Если затронута шапка — открыть мобильное меню и убедиться, что оно на весь экран и прокручивается.

Скриншоты делаются в headless Chromium (`CHROME_PATH` или `/opt/pw-browsers/...`). Карта Яндекса в нём пустая — это нормально.

## Если пользователь сообщает о баге

- Попробуй воспроизвести на той же ширине (iPhone 15 — 393, 15 Pro Max — 430, узкие Android — 360).
- Помни про кэш: GitHub Pages кэширует до 10 минут, а Safari при перезапуске может показать вкладку из своего кэша. Пример — «меню на две строки» оказалось старой версией страницы.
- Jivo проверяй на реальном виджете: сборка с `PUBLIC_JIVO_ID=sJNQnSEwuL`, мобильный viewport + touch + UA iPhone, прокрутка, ожидание ~10 с.

## Полное ревью

Когда нужно проверить сайт целиком — два субагента по очереди:
1. **Ревьюер** (только читает): страницы всех типов на десктопе и телефоне, плюс программный обход всех HTML в `dist/` (пустые элементы, отступы из `&nbsp;`, таблицы, дубли заголовков, переполнение). Результат — отчёт с приоритетами, примерами URL, числом затронутых страниц и предложением правки.
2. **Исправитель**: правит по отчёту, без коммита. Решения уровня продукта (поиск, фильтры, смена названий товаров) отдельно согласовать с пользователем.

Перед пушем работы субагента — сам проверь сборку и ключевые скриншоты и покажи пользователю.
